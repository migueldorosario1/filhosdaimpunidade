## ERRO-LAURA-CLAUDE-20260815-0255-LOCK-ANTES-DO-PUSH

```yaml
ts_brt: 2026-08-15T02:55:00-03:00
severidade: MEDIA
area: GIT_PONTE
ref: ../mensagens/claude/20260815_024900_claude_ronda_007.md
estado: CORRIGIDO
```

**Esperado:** liberar o lock somente após confirmar o push da ronda 007.

**Aconteceu:** o comando encadeado liberou o lock mesmo com o push rejeitado
por fast-forward (o remoto tinha avançado com o sync das 02:52). O commit
ficou apenas local por ~1 minuto.

**Causa:** encadeamento `push | tail && rm lock` — o `tail` retorna sucesso
mesmo quando o push falha, então a liberação do lock não dependia do
resultado real do push.

**Correção:** lock readquirido, `git pull --rebase` (não destrutivo, commit
próprio reaplicado limpo) e push confirmado em `36467009`.

**Prevenção:** verificar o resultado real do push (exit code do próprio
`git push`, sem pipe) antes de liberar o lock; em caso de rejeição, manter o
lock e resolver com rebase não destrutivo.

**Verificação:** próxima ronda usará a sequência corrigida.

## ERRO-LAURA-CLAUDE-20260815-1452-LOCK-LOOP-SEM-VERIFICACAO

```yaml
ts_brt: 2026-08-15T14:53:00-03:00
severidade: BAIXA
area: GIT_PONTE
ref: ../mensagens/claude/20260815_145347_claude_ronda_031.md
estado: CORRIGIDO
```

**Esperado:** o ritual só prossegue após posse confirmada do lock.

**Aconteceu:** na abertura da ronda 031 (14:52), o laço de aquisição esgotou
as tentativas sem adquirir (lock com LAURA-CODEX desde 14:48) e, mesmo
assim, o encadeamento executou o `git pull` — o `for` retorna sucesso
independentemente do resultado. O pull foi somente leitura e não houve dano
nem escrita, mas o formato permitia operar sem posse.

**Causa:** mesma família do ERRO-0255 (encadeamento que não verifica o
resultado real da etapa crítica): `for ... done && git pull` — o `&&` testa
o laço, não a aquisição.

**Correção:** sequência refeita na própria ronda com flag `ACQUIRED` e
aborto explícito (`LOCK NAO ADQUIRIDO — abortando`) antes de qualquer Git.
Lock então adquirido legitimamente às 14:53 (12ª tentativa).

**Prevenção (muda o formato):** toda etapa crítica do ritual carrega
verificação explícita do seu resultado real — padrão já aplicado ao push
(exit code), agora ao lock (flag de posse). Nunca confiar no status de um
laço/pipe como proxy do resultado.

**Verificação:** ronda 032 usará a sequência com flag desde a primeira
tentativa.
